# .actrc — execução local (nektos/act)

`act` roda o workflow **localmente em Docker**, com o celular no USB do host.

## Requisitos

- Linux (macOS/Windows **não** fazem passthrough de `/dev/bus/usb` no Docker Desktop)
- Docker com acesso a `/dev/bus/usb` (o `--privileged` está no `.actrc`)
- `adb` e `fastboot` no host, udev liberando o device (`android-sdk-platform-tools-common`)
- celular com depuração USB ativa e bootloader destravado (para HIL)

## Uso

```bash
# 1) validar ambiente + imagem do runner
act -l -W workflows-local

# 2) sem flash: só auditoria estática
act -W workflows-local -j static-audit

# 3) com flash no slot de staging (mutate=true)
act -W workflows-local -j stage-slot \
  --input test_slot=b --input prod_slot=a --input mutate=true

# 4) promoção (só depois de PASS)
act -W workflows-local -j promote --input promote=true
```

## Segurança

- `.actrc` **não** guarda token. Se algum job precisar de `GITHUB_TOKEN`:
  `act -s GITHUB_TOKEN="$(gh auth token)"`.
- `--privileged` + `/dev/bus/usb` dá ao container acesso ao aparelho: rode só na sua máquina.
- O workflow que faz `fastboot flash` vive em `workflows-local/`, **nunca** em `.github/workflows/`;
  nenhum push dispara escrita no celular.
