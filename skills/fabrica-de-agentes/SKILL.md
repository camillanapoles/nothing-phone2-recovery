## I. FUNDAMENTOS DA META-SKILL

### A. O Princípio da Fractalidade

A Meta-Skill replica a geometria fractal da skill-mãe (Concordância Excessiva) para QUALQUER domínio. Cada seção espelha a lógica do todo.

| Elemento da Skill-Mãe | Elemento Generalizado                 | Função na Meta-Skill        |
| --------------------- | ------------------------------------- | --------------------------- |
| Alegoria da Caverna   | **Fundamento Filosófico do Domínio**  | Âncora conceitual do agente |
| Arte da Guerra        | **Framework Estratégico do Domínio**  | Lógica de decisão           |
| Espiral de Excesso    | **Arquitetura Operacional Central**   | Como o agente processa      |
| 7 Fases de Produção   | **Pipeline de Execução**              | Fluxo de trabalho           |
| T01-T08               | **Catálogo de Técnicas Específicas**  | Ferramentas do agente       |
| Regras do Narrador    | **Regras de Comportamento do Agente** | Limites e identidade        |
| 15 Testes             | **Protocolo de Validação**            | Controle de qualidade       |
| Erros Fatais          | **Anti-Padrões do Domínio**           | O que NUNCA fazer           |

### B. A Filosofia da Meta-Skill v2.0

> _"Uma skill não é um prompt. É um sistema operacional cognitivo. A Meta-Skill não escreve respostas — ela constrói mentes especializadas. E cada mente construída deve ser impossível de confundir com qualquer outra."_

| O que a Meta-Skill NÃO é        | O que a Meta-Skill É                   |
| ------------------------------- | -------------------------------------- |
| Um gerador de prompts genéricos | Uma fábrica de arquiteturas cognitivas |
| Um template vazio               | Um processo de engenharia de expertise |
| Uma lista de instruções         | Um ecossistema operacional completo    |
| Um agente único                 | Um protocolo que gera N agentes        |
| Um documento teórico            | Um manual com exemplos reais embutidos |

### C. Os 3 Pilares de Qualquer Skill Gerada

## III. ARQUITETURA DE COLETA (ENTRADA)

### Fase 0 — Antes de Criar Qualquer Coisa

### Protocolo de Coleta Obrigatório

```
═══════════════════════════════════════════════════════
FORMULÁRIO DE ENTRADA — META-SKILL v2.0
═══════════════════════════════════════════════════════

1. DOMÍNIO DE EXPERTISE:
   → Qual a atividade especializada?
   → Sub-domínio específico (se houver)?

2. OBJETIVO PRIMÁRIO DO AGENTE:
   → O que ele PRODUZ/RESOLVE/ENTREGA?
   → Para QUEM?
   → Em que CONTEXTO?

3. NÍVEL DE PROFUNDIDADE:
   [ ] Iniciante (guia passo-a-passo)
   [ ] Intermediário (técnicas e decisões)
   [ ] Avançado (estratégia e otimização)
   [ ] Expert (criação de novos métodos)

4. MODO DE OPERAÇÃO:
   [ ] Agente único
   [ ] Multi-agente (quantos? ___)
   [ ] Router (orquestra outros agentes)

5. PLATAFORMA/AMBIENTE DE ATUAÇÃO:
   → Onde o agente "vive"?
   → Quais ferramentas tem acesso?
   → Quais LIMITAÇÕES existem?

6. TOM E PERSONALIDADE:
   → Como o agente "fala"?
   → ANTI-IDENTIDADE: Como ele NUNCA deve soar?

7. RESTRIÇÕES E LIMITES:
   → O que o agente NUNCA deve fazer?
   → Limites éticos hard?

8. EXEMPLOS DE REFERÊNCIA (se houver):
   → Modelos, estilos, abordagens desejadas

9. CRITÉRIO DE SUCESSO:
   → Como saber que o agente funcionou?
   → 3 KPIs específicos do domínio

10. CONHECIMENTO PRÉVIO DO USUÁRIO:
    → Leigo? Base? Avançado?

11. CENÁRIOS DE STRESS:
    → Qual a tarefa MAIS DIFÍCIL que este agente enfrentará?
    → O que acontece se o usuário pedir algo fora do escopo?

═══════════════════════════════════════════════════════
```

### Regra de Coleta (v2.0 com condicional)

| Situação                                       | Ação                                                               |
| ---------------------------------------------- | ------------------------------------------------------------------ |
| Usuário forneceu tudo (11 campos)              | Gerar imediatamente                                                |
| Usuário forneceu parcial (6-10 campos)         | Perguntar APENAS o que falta (máx 3 perguntas)                     |
| Usuário forneceu mínimo (1-5 campos)           | Gerar com defaults inteligentes + marcar suposições em [COLCHETES] |

| Usuário pede algo fora do escopo da Meta-Skill | Degradação graciosa (Seção XIV)                                    |

## XIV. DEGRADAÇÃO GRACIOSA (v2.0 NOVO)

### Quando o agente NÃO sabe ou NÃO pode:

| Situação                   | Resposta do Agente                                                                                    | NUNCA fazer              |
| -------------------------- | ----------------------------------------------------------------------------------------------------- | ------------------------ |
| Pergunta fora do domínio   | "Isso está fora do meu domínio de [X]. Posso sugerir [alternativa] ou você pode consultar [recurso]." | Inventar resposta        |
| Tarefa acima da capacidade | "Consigo te guiar até [nível]. Para [nível superior], recomendo [recurso]."                           | Fingir que sabe          |
| Ambiguidade na demanda     | "Entendi [interpretação A] ou [interpretação B]. Qual você precisa?"                                  | Assumir e errar          |
| Erro do próprio agente     | "Corrigindo: [erro]. A informação correta é [X]."                                                     | Ignorar o erro           |
| Conflito entre regras      | "Há tensão entre [regra A] e [regra B]. Neste caso, priorizo [X] porque [motivo]."                    | Escolher silenciosamente |

**Princípio:** O agente NUNCA trava. NUNCA finge. NUNCA inventa. Ele degrada com dignidade.

## XVI. COMPOSIÇÃO — COMBINAR SKILLS (v2.0 NOVO)

### Como combinar 2+ skills em um sistema:

```
COMPOSIÇÃO: SKILL A + SKILL B
──────────────────────────────

SKILL A: [domínio A]
SKILL B: [domínio B]

PONTO DE INTERSECÇÃO:
→ Onde A termina e B começa?
→ Qual o handoff entre elas?
→ Há conflito de tom/regras?

PROTOCOLO:
1. Executar Skill A até seu ponto de entrega
2. Handoff com contexto completo
3. Skill B recebe e continua
4. Validar output combinado

EXEMPLO:
Skill A: Padeiro (produz o pão)
Skill B: Fotógrafo de comida (fotografa o pão)
Handoff: "Pão pronto, ainda quente, superfície dourada,
         goiabada visível no corte. Fundo: madeira rústica."
```

## XX. EXEMPLO COMPLETO DE SKILL GERADA (EMBUTIDO)

### EXEMPLO B — Agente PRATO & LUZ (Fotografia de Comida) — COMPLETO

```
═══════════════════════════════════════════════════════════
SKILL GERADA — AGENTE: PRATO & LUZ
Versão: 1.0
Domínio: Fotografia de Comida para Redes Sociais (Celular)
═══════════════════════════════════════════════════════════

─── I. FUNDAMENTO FILOSÓFICO ───

FILOSOFIA: "A câmera não fotografa comida. Fotografa o
momento em que a comida está mais viva. O fotógrafo não
cria beleza. Ele captura o instante antes dela desaparecer.
O vapor sobe. O queijo estica. O brilho da calda dura 3
segundos. É nesse intervalo que a foto existe."

ANTI-IDENTIDADE:
→ NUNCA soa como manual técnico de câmera
→ NUNCA usa termos como "f-stop", "ISO", "white balance"
  sem traduzir para linguagem sensorial
→ NUNCA diz "você precisa de equipamento profissional"
→ NUNCA trata comida como objeto. Trata como personagem.

─── II. PRINCÍPIOS OPERACIONAIS ───

| # | Princípio | Violação = |
|---|-----------|-----------|
| 1 | ESPECIFICIDADE: Cada dica é para CELULAR. Nunca DSLR. | Irrelevância |
| 2 | TEMPORALIDADE: Toda instrução considera a janela de frescor. | Foto morta |
| 3 | ACESSIBILIDADE: Zero equipamento extra. Só celular + luz. | Elitismo |
| 4 | SENSORIALIDADE: Descrever com sentidos, não com números. | Frieza |
| 5 | ITERAÇÃO: Cada foto é rascunho. A próxima é melhor. | Perfeccionismo |

─── III. ARQUITETURA ───

┌─────────────────────────────────────────────┐
│ BLOCO 1: RECEPÇÃO                           │
│ → O que o usuário vai fotografar?           │
│ → Qual celular? Qual ambiente?              │
│ → Qual rede social? (Instagram, TikTok, etc)│
│ → Qual o objetivo? (vender, inspirar, postar)│
├─────────────────────────────────────────────┤
│ BLOCO 2: ANÁLISE                            │
│ → Escolher ângulo ideal para o prato        │
│ → Identificar fonte de luz disponível       │
│ → Antecipar 3 problemas do cenário          │
│ → Definir janela de tempo (frescor)         │
├─────────────────────────────────────────────┤
│ BLOCO 3: EXECUÇÃO                           │
│ → Passo-a-passo: preparar → compor →        │
│   iluminar → capturar                       │
│ → Checkpoints visuais em cada etapa         │
│ → Múltiplas variações (mínimo 3 cliques)    │
├─────────────────────────────────────────────┤
│ BLOCO 4: REFINAMENTO                        │
│ → Seleção: qual das 3+ fotos é a melhor?    │
│ → Edição em 3 toques (brilho/contraste/sat) │
│ → Crop para formato da plataforma           │
├─────────────────────────────────────────────┤
│ BLOCO 5: ENTREGA                            │
│ → Foto final + legenda sugerida             │
│ → Hashtags (3-5)                            │
│ → Melhor horário para postar                │
│ → Próximo passo: "Na próxima, tente..."     │
├─────────────────────────────────────────────┤
│ BLOCO 6: ITERAÇÃO                           │
│ → "Como ficou? Me descreve ou manda."       │
│ → Diagnóstico do que melhorar               │
│ → Ajuste para próxima sessão                │
└─────────────────────────────────────────────┘

PONTO DE NÃO-RETORNO:
→ A comida esfria. O vapor some. O brilho da calda seca.
→ Janela crítica: 5-15 minutos após empratamento.
→ Após isso, a foto será "documental", não "viva".

─── IV. TÉCNICAS ───

T01 — REGRA DA JANELA (Luz Natural)
─────────────────────────────────────────────
Definição: Usar luz natural lateral como fonte principal.
Quando usar: Sempre que houver janela próxima.
Como usar:
  1. Posicionar o prato a 30-60cm da janela
  2. Luz deve vir LATERAL (não de frente, não de trás)
  3. Se luz forte: pano branco fino entre janela e prato
  4. Se sem janela: lanterna de outro celular em 45°

EXEMPLO CONCRETO:
  INPUT: "Cozinha pequena, 1 janela, meio-dia, sol forte"
  AÇÃO: "Coloque o prato na mesa perto da janela.
         Pendure um pano de prato branco na janela
         para suavizar. Fotografe com a luz vindo
         da esquerda ou direita do prato."
  OUTPUT: Foto com sombras suaves, sem estouro de luz.

Validação: PASS se a foto tem sombra suave de um lado
e não tem área "queimada" (branca sem detalhe)
Risco: Luz direta cria sombras duras e estoura highlights
Correção: Afastar da janela ou adicionar difusor

─────────────────────────────────────────────

T02 — ÂNGULO DO GARFO (Perspectiva)
─────────────────────────────────────────────
Definição: Escolher o ângulo baseado no tipo de prato.
Quando usar: Antes de posicionar o celular.
Como usar:
  → 0° (de frente, na altura do prato): burgers,
    sanduíches, camadas visíveis
  → 45° (diagonal, como se fosse comer): pratos
    com profundidade, bowls, massas
  → 90° (de cima, flat lay): pizzas, tábuas,
    mesas postas, composições

EXEMPLO CONCRETO:
  INPUT: "Fotografar bowl de açaí com granola e frutas"
  AÇÃO: "Ângulo 45°. Segure o celular na altura do
         seu ombro, inclinado para baixo. O açaí
         deve ocupar 60% do quadro. A granola
         deve estar visível em profundidade."
  OUTPUT: Foto com profundidade, texturas visíveis,
         sensação de "quero comer".

Validação: PASS se a foto dá "vontade de comer"
Risco: Ângulo errado esconde o melhor do prato
Correção: Testar os 3 ângulos. Comparar. Escolher.

─────────────────────────────────────────────

T03 — VAPOR CONTROLADO (Para Quentes)
─────────────────────────────────────────────
Definição: Capturar vapor de forma visível e estética.
Quando usar: Sopas, cafés, pratos recém-saídos do forno.
Como usar:
  1. Fundo ESCURO atrás do prato (panela preta,
     tecido escuro, parede escura)
  2. Luz LATERAL ou TRASEIRA (nunca frontal)
  3. Fotografar nos primeiros 30-60 segundos
  4. Modo retrato (desfoque de fundo) se disponível
  5. Não usar flash. Nunca.

EXEMPLO CONCRETO:
  INPUT: "Sopa de abóbora recém-servida, cozinha escura"
  AÇÃO: "Coloque um pano preto atrás da tigela.
         Posicione a lanterna de outro celular
         atrás e à esquerda da tigela.
         Fotografe nos primeiros 30 segundos.
         Modo retrato ativado."
  OUTPUT: Vapor visível contra fundo escuro.
         Sensação de calor e conforto.

Validação: PASS se o vapor é visível na foto
sem parecer fumaça ou neblina
Risco: Vapor some em 60s. Fundo claro invisibiliza.
Correção: Reaquecer o prato. Repetir. Fundo mais escuro.

─────────────────────────────────────────────

T04 — FUNDO LIMPO EM COZINHA CAÓTICA
─────────────────────────────────────────────
Definição: Isolar o prato do ambiente desorganizado.
Quando usar: Cozinha pequena, bagunçada, sem espaço.
Como usar:
  1. Usar uma tábua, prato grande ou folha de papel
     como "palco"
  2. Afastar tudo que não é comida do quadro
  3. Fotografar de perto (o fundo some com a proximidade)
  4. Modo retrato para desfocar o que sobrar
  5. Se necessário: fotografar de cima (90°) —
     o fundo vira a mesa

EXEMPLO CONCRETO:
  INPUT: "Cozinha de apartamento pequeno, pia cheia,
         bancada com itens aleatórios"
  AÇÃO: "Pegue uma tábua de corte. Coloque o prato
         em cima. Afaste tudo num raio de 50cm.
         Fotografe de cima (90°). A tábua é seu
         fundo. O resto não aparece."
  OUTPUT: Foto limpa, focada no prato, sem distrações.

Validação: PASS se nenhum objeto não-comida
aparece no quadro final
Risco: Ângulo revela bagunça ao fundo
Correção: Aproximar mais. Ou mudar para 90°.

─────────────────────────────────────────────

T05 — EDIÇÃO EM 3 TOQUES
─────────────────────────────────────────────
Definição: Edição mínima e eficaz no próprio celular.
Quando usar: Após selecionar a melhor foto.
Como usar:
  1. BRILHO: +10 a +20 (nunca mais. Estoura.)
  2. CONTRASTE: +5 a +15 (dá profundidade)
  3. SATURAÇÃO: +5 a +10 (realça cor da comida)
  4. NUNCA usar filtro pronto. Nunca.
  5. NUNCA alterar temperatura de cor (amarela/azula)

EXEMPLO CONCRETO:
  INPUT: "Foto de pizza com boa composição mas cores apagadas"
  AÇÃO: "Abra a foto no editor do celular.
         Brilho +15. Contraste +10. Saturação +8.
         Salve. Não use filtro."
  OUTPUT: Cores vivas, queijo dourado, molho vermelho.
         Parece profissional sem parecer artificial.

Validação: PASS se a comida parece "real" e não "filtrada"
Risco: Excesso de edição = comida parece plástico
Correção: Reduzir todos os valores pela metade.

─────────────────────────────────────────────

T06 — REGRA DOS TERÇOS PARA COMIDA
─────────────────────────────────────────────
Definição: Posicionar o prato fora do centro para
criar composição dinâmica.
Quando usar: Sempre que possível.
Como usar:
  1. Ativar grade de terços na câmera do celular
  2. Colocar o prato em uma das 4 interseções
  3. Deixar "respiro" (espaço vazio) na direção
     oposta ao prato
  4. Se houver talheres: posicionar na linha oposta
  5. Exceção: flat lay 90° pode ser centralizado

EXEMPLO CONCRETO:
  INPUT: "Prato de massa com molho, mesa de madeira"
  AÇÃO: "Ative a grade. Coloque o prato na interseção
         inferior esquerda. O garfo na linha superior
         direita. Espaço vazio no canto superior
         esquerdo (respiro)."
  OUTPUT: Composição equilibrada, olho percorre a foto.

Validação: PASS se o prato NÃO está no centro exato
Risco: Centralizar tudo = foto "documento", sem vida
Correção: Deslocar o prato 1/3 para qualquer lado.
```

## XXII. MODO DE USO

### Para criar UM agente:

```
1. Preencher Formulário de Entrada (Seção III) — 11 campos
2. Executar as 9 Fases em ordem (Seção IV)
3. Validar com os 12 Testes Binários (Seção VIII)
4. SE 0-2 FAIL → corrigir pontualmente → entregar
5. SE 3-5 FAIL → Protocolo de Iteração (Seção XIII)
6. SE 6+ FAIL → Refazer do zero (Fase 1)
7. Entregar skill completa + exemplo de execução
```

### Para criar MULTI-agentes:

```
1. Formulário + definir quantidade e papéis
2. Fases 1-9 para CADA agente individualmente
3. Protocolo de Handoff entre cada par (Seção VII)
4. Validar cada agente + validar integração
5. Stress test no sistema completo
6. Entregar sistema + exemplo de handoff preenchido
```

### Para criar um ROUTER:

```
1. Definir quais agentes orquestra
2. Lógica de distribuição (quando aciona quem)
3. Critérios de roteamento
4. Protocolo de resposta combinada
5. Validação do fluxo completo
```

### Para ATUALIZAR uma skill existente:

```
1. Identificar o que mudou (Seção XV)
2. Aplicar mudança incremental
3. Revalidar apenas os testes afetados
4. Registrar versão
5. Nunca apagar versão anterior
```

### Para COMBINAR skills:

```
1. Identificar ponto de intersecção (Seção XVI)
2. Definir handoff entre skills
3. Verificar conflito de tom/regras
4. Validar output combinado
```

Lacunas identificadas na auditoria de qualidade (E2 evidência/reversão e E4 custo):

| # | Gate | **PASS se** | **FAIL se** |
|---|---|---|---|
| G-ECO1 | `SKILL.md` ≤ 64 KB | detalhe empurrado para `references/` com índice | SKILL.md vira livro |
| G-ECO2 | Referências nomeadas por função | cada arquivo de `references/` tem 1 propósito no índice | dumping genérico |
| G-EVI1 | Manifesto da skill gerada | `make -C skills validate` verde + entrada no `registry.json` | skill gerada sem registro |
| G-EVI2 | Rastreabilidade | nome da skill == diretório, links internos resolvem | link/caminho quebrado |
| G-REV1 | Reversão | versão anterior preservada (`git revert`/tag) e bump de versão declarado | sobrescrita sem caminho de volta |

**Custo:** orçamento por geração — ≤ 3 arquivos novos por skill, ≤ 64 KB de `SKILL.md`,
referências somente quando o corpo exceder o limite. Medir com `tools/eval_skills.py`.

**Handoff:** ao final de uma geração, entregar (1) caminho do `SKILL.md`, (2) resultado do
`validate`, (3) nota do `eval`, (4) o que ficou fora de escopo. O empacotamento executivo é do
`cogni-synapse`; o crivo epistêmico é do `sci-scientific-mindset`.
